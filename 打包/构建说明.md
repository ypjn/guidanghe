# macOS 应用构建

目标是 Apple 芯片上的 `归档盒.app` 和只读 DMG。脚本不写死某台电脑的解释器路径。

## 环境

- macOS 12 或更新版本，Apple 芯片
- Python 3.14，并安装与 `归档盒源码/requirements.txt` 相同的依赖
- PyInstaller 6.22（本机已验证；其他 6.x 需重新做启动验收）
- 系统自带的 `iconutil`、`hdiutil`、`codesign`

仓库里可以没有 `.venv`。把可用解释器交给构建脚本：

```sh
export ARCHIVEBOX_BUILD_PYTHON="/path/to/python"
zsh 打包/build_mac.sh
```

未设置环境变量时，脚本才会使用仓库内的 `归档盒源码/.venv/bin/python`。打包命令是 `python -m PyInstaller`。

依赖可以装进单独的虚拟环境：

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r 归档盒源码/requirements.txt PyInstaller==6.22.3
```

## 产物

- `打包/dist/归档盒.app`
- `打包/dist/归档盒-1.8.0-macos-arm64.dmg`
- `打包/dist/SHA256SUMS.txt`

DMG 里有应用、指向“应用程序”的快捷方式和拖入说明。格式是压缩只读镜像。脚本会做本地 ad-hoc 签名，使本机可以启动。Apple 开发者签名和公证还没做，不能靠关闭系统安全检查代替。

安装后的启动日志在用户日志目录（macOS 为 `~/Library/Logs/归档盒`）。方案库、全局偏好和最近空间仍在应用数据目录。每个整理空间的历史和偏好仍在该空间的 `.organizer`。

## 验收

```sh
zsh 打包/accept_mac_app.sh 打包/dist/归档盒-1.8.0-macos-arm64.dmg /path/to/evidence
```

验收程序直接运行应用可执行文件，并记录该进程的退出码。
