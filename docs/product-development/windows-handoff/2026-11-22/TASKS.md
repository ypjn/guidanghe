# Windows 实施任务与验收

这份文档是原第05–07批在Windows的执行规格。先完成搜索修复，不重复开发已有第01–04批。

## 0. Windows环境和基线

- 核对仓库、分支、未提交改动、当前提交与交接基线祖先关系。已有更新保留；不回滚用户工作。
- 优先使用合适的已有原生Python环境。检查实际解释器/库目录，Python版本、PySide6、pypdf、SQLite/FTS5、Windows架构与系统版本。项目当前已验证的依赖见`归档盒源码/requirements.txt`；环境标记应按Windows实际计算。
- 没有合适环境时建立独立项目环境并安装必要依赖，不复用Mac虚拟环境。源码入口为`归档盒源码/main.py`。
- `pyobjc-framework-Vision`仅Mac使用；Windows OCR按当前实现与实际语言包支持检查。不要把可选OCR缺失混为核心搜索不能运行。
- 检查长路径实际设置、桌面权限、盘类型和文件系统，不擅改系统全局设置来掩盖不兼容。
- WSL已安装不代表Windows桌面或GPU已验证，本轮不需要GPU。资源足够时再扩规模，不做无上限并行解析。
- 测试通过`ARCHIVEBOX_APP_DIR`、`ARCHIVEBOX_LOG_DIR`、`ARCHIVEBOX_INDEX_DB`等实际支持入口隔离，避免污染个人配置。

## B. 第05批：外置盘只读索引与离线目录

### 要实现

1. 用户登记明确的外置盘目录；记录空间ID、目录、可靠卷身份、文件系统、在线状态与最近成功索引时间。索引在本机用户目录，不在来源盘写任何应用文件。
2. 复用已有SQLite索引、增量扫描和状态，不做第二套互不兼容的注册表。迁移有版本和事务，保留旧空间、索引、偏好和历史。
3. 盘离线后保留最近可用目录和允许保留的正文，结果显示设备离线及索引时间。禁止打开陈旧路径。重连先核对可靠身份；盘符或卷名不能独自证明是同一盘。
4. 取消、I/O失败、子目录权限失败、断连不等于文件全部被删除。只有确认完整成功枚举的范围才可据此标记删除。
5. 支持启用/暂停、刷新、移除登记和清理本地正文；移除不删除源资料。索引权限与整理保护分别执行。
6. 本批不做跨盘移动、自动同步或清理来源。

### 真盘和隔离样本验收

- 先让用户指定资料只读目录和可写的测试目录；已指定即可在其中建立带随机ID的测试子目录。未知盘或未知路径不写入。
- 真盘测试使用指定样本，记录当前文件系统和实际支持范围。有NTFS就测NTFS，有exFAT就测exFAT，不格式化现有盘凑覆盖。
- 原生界面登记→索引→中文搜索/定位→无写入任务时由用户安全弹出→离线查找→重连刷新。
- 卷身份变化、同名换盘、盘符变化/路径复用、只读或权限失败、长路径、中文名、同名不同内容、大小写冲突、junction/符号链接逃逸均有夹具或实测；没权限建立某类链接则明确待测，不写通过。
- 断连时索引保留；错误设备不能被识别为旧盘，不能打开另一设备同名文件。危险的写入中断用故障注入或可丢弃介质，不强制拔真实数据盘。
- 原资料和只读索引范围的路径、数量、内容指纹不变。应用无新增`.organizer`、缓存、标记；有测试夹具写入时与只读索引动作分开记录。

## C. 第06批：本地版本备份与安全恢复

### 要实现

1. 手动选择来源与独立仓库，预览文件数、总量、新增占用、排除项和元数据支持，确认后开始。备份仓库不得与来源相互嵌套或经链接重叠，并排除在索引/整理默认范围外。
2. 每版有相对路径、大小、SHA-256、来源身份、备份时间和实际保存的元数据。临时写入→内容校验→落位→清单提交；未完整提交不能显示可恢复完成。
3. 增量复用必须有可核验依据，不把不可靠的stat相同当成内容未变保证。不对来源建硬链接；恢复复制而不是硬链接到历史对象。
4. 源复制中变化、空间不足、权限失败、仓库只读/断连、取消/崩溃、损坏清单/对象都有准确失败状态。备份不改源、不删源，不镜像传播删除，不自动清理旧版本。
5. 默认恢复到新的空目录，不覆盖现有文件。拒绝绝对路径、`..`、Windows保留名、大小写冲突、链接/junction逃逸和中途目标替换；范围外哨兵不变。
6. 能看版本和逐项结果、验证完整性、诊断失败。内容、路径、时间、权限、扩展属性分别说明实际支持，不宣传成系统备份或完整元数据恢复。
7. 保存范围与整理保护独立，用户可明确授权备份受保护项目；只读备份不能扩大移动权限。

### 验收

- 两版夹具：备份第一版→只修改样本→备份第二版→恢复到两个新空目录，与各自独立清单的路径/数量/SHA-256一致。
- 修改恢复文件不影响来源、备份和另一版；从未备份或校验失败的内容不能承诺恢复。
- 覆盖写满/取消/进程中断/清单提交前后中断/源变化/对象篡改/对象缺失/恶意清单/目标替换。
- 占用文件、长路径、中文、保留名、大小写和只读条件在Windows原生覆盖，失败明确而非静默漏备份。
- 真实盘只读与仓库写入是不同操作。初版仓库可先在本机指定目录，保证不与真实来源重叠。同一物理盘的备份不具备整盘损坏容灾能力。

## D. 第07批：Windows集成构建和原生验收

### 构建需要收口的现状

- `打包/build_windows.sh`是Mac交叉组装脚本，写死旧`.venv/bin/pip`和Darwin Go下载。补Windows PowerShell可重复构建入口，解释器/工具入口可配置，源目录按脚本相对位置定位。
- `打包/requirements-windows.txt`和旧脚本手写依赖列表遗漏`pypdf==6.4.0`；旧脚本未读取该依赖文件。统一可信依赖入口并验证部署，别只改一处文件。
- 旧使用说明仍写V1.7，数据说明也未区分全局目录与每空间`.organizer`。应用、说明、包名和构建身份应一致，版本/完整提交可追溯。
- 当前可优先沿用嵌入式Python+app源码+Go启动器的免安装结构，提供原生构建；无需同时迁移整个打包体系。Qt的`qwindows.dll`、PDF、新模块、可选OCR依赖应实际验证。
- 当前Go启动器不透传参数。要么安全补齐并测试参数透传，要么验收直接用包内Python启动app；启动器双击可见单独测。启动器返回0不能代替应用进程退出码。
- `57790f6`的Windows文件移动修复已在当前基线历史中，仍需新包实测。另有`fix/windows-launcher-hidden-window`历史分支，仅作为排错线索，先核对实际内容，不机械合并另一套启动器。

### 集成场景

1. 新用户：解压到非源码目录→双击可见窗口→登记空间→索引→PDF/中文搜索→翻页筛选→打开/定位→独立确认整理→退出重启→历史撤销。
2. 老用户：非空旧配置、偏好、最近目录、旧批次和索引升级后保留并可用；失败迁移有备份/诊断，不能删库初始化。
3. 真盘：只读登记、离线目录、安全重连。源码与包都验证，未测部分明确保留。
4. 备份：两版创建、完整性检查、分别恢复到新目录；内容和路径独立核对。
5. 并发与退出：边索引边查、快速换查询、旧任务晚到、取消重试、关窗/退出，没有旧结果覆盖、崩溃或残留进程。
6. 原生窗口至少检查100%/常用高DPI、长路径、非空结果、错误状态和关键按钮。实际未测的DPI或权限不写通过。
7. 至少一份真实可提取中文文字的PDF，以及后页命中和位置说明。扫描件准确提示不做OCR。
8. 包在干净隔离数据目录启动，不依赖开发环境的PYTHONPATH/源码绝对路径。运行不改安装包；打包前后和运行后的身份/指纹清楚。
