# 归档盒：TRAE 分轮提示词

本文件是开发前的提示模板，不是实际交互记录。不要一次性把全部轮次发送给 TRAE。每轮先保存结果并实际使用，再决定下一轮；可以根据真实反馈改写模板。后续每次追加提示同样单独记录。

## 首轮：环境核验与只读初版

```text
我要开发课程项目“归档盒”：一个本地桌面文件整理器。我要观察项目逐轮成长，因此本轮只实现 V0.1，不要一次性完成整个项目。

最终目标先告知你：选择目录，按文件类型/课程关键词分类，预览每个文件的目标位置，确认后整理；识别内容重复文件但保留所有副本；保存实际操作记录，支持重启后撤销最近批次；后续验证同名冲突、文件被修改、新文件占用原位置、取消和进程中断恢复。后续再分轮实现这些能力。

建议 Python + PySide6，核心文件逻辑与界面分离。先检查这台电脑实际可用的 Python 解释器、项目虚拟环境、PySide6 兼容性和最小窗口，不要假定依赖已经可用，不要更换系统 Python。说明采用的启动入口与需要安装的依赖。

本轮 V0.1 的工作：
1. 提供简洁中文桌面界面，可选择一个测试文件夹。
2. 递归扫描普通文件，显示文件名、相对路径、类型和大小，扫描中界面保持响应。
3. 跳过隐藏文件、.git、符号链接，以及预留的 _已整理 和 .organizer 目录；不跟随外部链接或跨文件系统挂载点。
4. 空目录、中文与空格文件名、无扩展名、无权限读取时有清楚反馈。
5. 只读扫描，不移动、删除、改名文件，也不在被扫描目录中创建日志或分类目录。
6. 使用单独的测试目录演示；不能操作我真实的下载目录、桌面资料或外接硬盘。

界面方向：工具型桌面应用，系统中文字体，蓝色主操作，清楚的文件表格和状态文字，不做大面积装饰图。

先简述本轮方案再实施；完成后实际启动检查，提供准确的运行方法、修改文件清单、实际验证结果和未验证项。不要把尚未执行的测试写成通过。
```

本轮应保留：完整原始聊天、环境检查输出、第一张运行截图、测试目录前后清单和 V0.1 源码版本。是否继续以实际运行结果为准。

## 第二轮：可解释分类与固定预览

```text
继续在现有归档盒上实现 V0.2，保留已经可用的扫描界面。本轮仍不移动文件。

增加“按类型”和“按课程再按类型”两种模式。课程仅按文件名中的关键词匹配，多条规则按显示顺序取第一条，未命中进入“未分类课程”。类型包括文档、课件、表格、图片、代码、压缩包和其他，扩展名大小写不敏感。

生成固定的整理计划，表格显示原位置、目标位置、分类依据、状态及勾选框。目标统一在所选根目录的 _已整理 内；不得生成越出目录的路径。同名文件及已有目标文件预先分配“名称 (1).扩展名”等唯一名称，按来源相对路径排序保证稳定。更改规则、根目录或分类模式必须使旧计划失效。

先用小型测试数据验证规则优先级、同名不同内容、目标已存在、无扩展名和中文路径。预览前后被扫描目录必须没有任何变化。保留旧功能并报告回归结果。
```

## 第三轮：整理与持久化基础撤销

```text
实现 V0.3：根据现有预览计划实际移动，并支持程序重启后撤销最近批次。

执行前确认根目录、勾选数量和目标。记录批次和逐项动作：原/目标路径、大小、SHA-256、状态、错误及本批次创建的目录。执行意图先持久化，再移动并记录结果，不要只在整批结束时写日志。执行器必须使用用户已确认的固定计划。

移动前核验源内容是否变化、目标是否被占用；变化项跳过并说明，不覆盖、不临时改成未预览的新名称。执行中防止重复点击启动。

基础撤销只处理实际移动成功的项目：检查目标仍存在且内容未改、原路径未占用，才能移回；否则保留现状并报告冲突。只清理本批次创建且当前为空的目录，不影响新增文件。重复撤销无副作用，重启后记录仍可用。

只在测试目录操作。先演示正常整理→关闭重开→撤销，再验证目标已存在和同名文件都不丢失。独立比较用户文件数量及内容指纹多重集合，不以界面显示成功代替验证。遇到失败保留原始输出后再修复。
```

## 第四轮：内容重复与撤销冲突

```text
在现有版本实现 V0.4。依据文件大小与 SHA-256 显示内容重复组；重复文件默认全部保留，不增加删除功能。同名不同内容不能被当成重复。

请用独立测试目录逐项检查：
1. 两份不同文件名但内容相同的文件；同名同大小但内容不同的文件。
2. 预览后修改源文件或新增目标占用。
3. 整理后在归档目录新建文件，再撤销。
4. 整理后修改一个被移动文件，再撤销。
5. 整理后在原位置放入新文件，再撤销。
6. 手动移走一个目标文件后撤销；重复撤销；关闭重开后撤销。

所有情况下不覆盖或删除用户后来变化的文件。冲突项保留并显示具体原因，其他项可继续；只部分恢复时显示部分撤销。先报告测试实际结果，发现问题后保存复现、修改原因与修复后回归结果。不要预先编造失败，也不要为了通过检查放宽原有标准。
```

## 第五轮：取消和进程中断恢复

```text
实现 V0.5：执行可取消；程序被终止后重启能核对未完成批次。

取消在当前单文件操作结束后生效，保存已完成部分，支持撤销。有未处理批次时先恢复或撤销，不能启动另一个批次。

中断恢复必须核对磁盘实际状态及内容指纹，不能把“日志没写成功”直接当成文件没移动。特别检查：一个文件已经移动，但该项完成记录尚未保存时进程退出。状态不明确时暂停该项并提示人工处理，不盲目重做。

使用测试专用检查点在不同执行阶段直接终止测试进程并重启，检查无丢失、无覆盖、无重复操作。不要修改生产逻辑制造 bug；人为终止只是测试输入，程序能否恢复才是结果。区分进程终止测试和未验证的断电/硬盘故障。

保存中断前后清单、原始日志、进程退出情况、恢复结果及完整回归。运行时间允许时再检查扫描和指纹计算的取消与界面响应。
```

## 第六轮：最终回归与交接

```text
暂停新增功能，对照开发前的验收清单完成现有功能复核。测试结果分为通过、未通过、未验证，给出可复现步骤和原始输出位置。

使用新的测试目录独立运行正常流程、同名冲突、重复副本、预览后变化、撤销冲突、取消和进程中断恢复。核验用户文件的内容指纹多重集合；完整撤销检查路径与内容恢复，冲突场景另行验证新建/修改内容得到保留。

修复后重跑受影响检查和已有核心回归，不删除失败检查、不降低验收标准。整理准确的运行说明、依赖与实际解释器、目录结构、限制和未解决问题。已有日志与历史版本不得覆盖，不替我编写没有发生的过程。

界面只做必要的可读性与操作反馈调整；不要在最终回归时重构整个项目或加入新功能。
```
