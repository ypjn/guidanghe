# 归档盒：产品目标与版本路线

日期：2026-11-07。

本文是未来产品规划，不代表下述功能已经实现。当前内部 V1.1 的课程过程记录和验收证据继续保留，后续目标单独立项，不改写过去的成功标准。版本号、数量和性能指标均为建议目标，按实际试用结果调整。

## 1. 产品定位

归档盒是一款本地桌面文件整理工具，帮助用户看懂文件现状、制定可解释的整理方案、确认后执行，并在出错或改变主意时查明记录、恢复文件。

首要用户是本人，优先解决课程、竞赛、项目、校园事务和个人资料的长期整理。先在 Mac 上形成持续使用的产品，再在拯救者的 Windows 原生环境验证，之后面向少量同学试用。公开分发建立在这两步之后。

长期价值：用户用更少的判断和重复操作维持清晰的资料结构，知道重要文件在哪里，也能理解软件对文件做过什么。

## 2. 当前起点与产品差距

已有基础包括扫描、固定计划、预览、内容重复识别、自动/手动保护、移动记录、撤销、中断恢复以及针对性回归。历史规模验收处理了 7140 个待整理文件，并使用 199366 条独立清单核对副本；清单条目数不是实际移动文件数。

当前仍有几个产品差距：

- 推荐模式的方向、学期和目录映射主要写在代码中；现有课程规则编辑没有接入推荐模式的这套映射，通用性和规则一致性需要改进。
- 任务取消、恢复过程、历史查看、执行进度尚未构成完整的日常操作体验。
- 启动依赖项目虚拟环境；仍需建立安装包、升级、数据兼容和新用户首次使用流程。
- 已有内容和路径核验不能自动证明所有文件元数据、其他系统及其他文件系统都已受支持。
- 学生个人项目需要逐步补齐独立仓库、可移植测试、配置版本和发布记录。

规划继续使用 Python + PySide6 + SQLite。当前环境已核验 Python 3.14.8、PySide6 6.12.0 入口；新部署方案和 Windows 环境另做小样验证。暂不因产品化而整体更换技术栈。

## 3. 发布原则

1. 文件安全优先。目标是零意外覆盖、零误删、零无法解释的丢失；发生相关事件即停止发布并定位，不用其他测试的高通过率抵消。
2. 每次执行对应用户确认的计划；规则、目录或输入变化后重新校验。
3. 无法读取或验证的文件明确提示并暂停受影响动作，避免在证据不足时执行。
4. 保护目录保持原位；未来的“整包归档”是另一种明确操作，不能混用语义。
5. 每次操作有可查询记录；不可恢复的情况明确说明，不承诺覆盖断电或损坏等未经验证的场景。
6. 先做用户确认的整理，再逐步开放指定目录、指定规则下的自动执行。
7. 核心功能离线可用。未来的 OCR、模型分类和联网服务是可选能力。
8. 整理记录不等于备份。试用初期在有可恢复备份的资料上逐步扩大使用范围。

## 4. 阶段一：V1.2，让本人可以持续使用

### 目标

形成可停止、可查询、可恢复的完整操作流程。

### 工作

- 扫描、指纹计算、恢复核对移入统一任务管理；明确各阶段的开始、取消、结束和关闭规则。
- 显示当前文件、已处理数量、失败原因、取消状态。明确哪些步骤可以立即停止，哪些需要等待当前安全步骤完成。
- 增加历史页面：批次、逐项原/目标路径、状态、错误、撤销与恢复入口；支持导出可读记录。
- 增加预览搜索、筛选、批量勾选、目标树视图和完整路径查看。
- 复核文件操作层的不覆盖语义、源/目标变化检查、指纹读取失败、同一整理空间的多实例互斥。
- 大目录表格按需加载；分离文件操作逻辑和界面任务控制，逐步拆分 main.py 的职责。
- 建立独立源码仓库、依赖声明、相对路径测试入口和互不污染的测试目录；个人路径与资料不写入通用默认配置。

### 完成条件

- 正常、取消、失败、关闭和恢复均能从界面完成，不需要开发者手动改数据库。
- 同一整理空间被第二个实例打开时，能够阻止重复执行。
- 对指纹失败、目标占用、输入变化等实际异常有明确结果和可复现测试。
- 以已有约 7000 个待处理文件的样本建立性能基线；界面大多数操作在 200 ms 内反馈，大文件等待时持续显示当前阶段。
- 在备份充分的本人资料上连续使用四周，记录至少 20 次真实整理任务及所有问题；将“无需改源码完成整理”作为核心观察指标。

## 5. 阶段二：V1.3，让整理方案真正可配置

### 目标

用户无需修改代码，就能建立和调整适合自己资料的整理方案。

### 工作

- 新增整理空间：每个来源目录独立保存规则、保护项、目标位置与历史。
- 将学期、课程、方向、类别与目录锚点改为可编辑配置；明确不同模式使用哪些规则。
- 支持按文件名、路径、扩展名等条件组合规则，提供优先顺序、启用开关、导入导出和配置版本。
- 编辑规则时试运行，显示命中数量、代表样本、冲突及未分类项，并说明分类依据。
- 支持修改单个或一组文件的分类结果；明确“只修正本次计划”和“保存为以后使用的规则”。
- 目标目录支持用户选择和层级模板；初期保持在已支持的同卷边界内。
- 项目目录默认保留原位。后续增加明确的“整包归档”选项时，单独验证结构、链接和实际可用性；整包移动也不承诺修复项目原有绝对路径依赖。

### 完成条件

- 你能够仅通过界面配置第二阶段选定目录，不再为新课程、新学期或新类别修改 planner.py。
- 修改规则后推荐模式实际生效，旧计划及时失效；重启和升级保留配置。
- 建立约 300 条分层人工标注样本，包含常见资料和容易误判的文件。初始目标为高置信建议正确率不低于 95%，并同时报告覆盖率与待确认比例。
- 不把“匹配到规则”直接当作“语义分类正确”。准确率是分类建议指标，不能放宽文件安全标准。

## 6. 阶段三：V1.4，让日常新增文件持续变得有序

### 目标

从一次性清理目录，发展到持续管理每周新增的资料。

### 工作

- 提供待整理收件箱，支持拖入文件或目录。
- 支持增量扫描和指纹缓存，说明缓存失效条件；实际执行前保留必要的文件验证。
- 监测用户指定目录，把新文件形成待确认建议；首次支持监测时默认只建议。
- 增加重复文件查看：内容重复、同名不同内容、不同版本分别展示，用户可以打开原文件核对。
- 支持按课程、项目、日期和历史位置查找文件，并在系统文件管理器中定位。
- 记录用户对分类的修正，把建议改进限定在可查看、可撤回的规则变化中。

### 完成条件

- 每周新增课件、作业、截图等可沿用既有方案整理，用户不必反复建立分类结构。
- 只有少量新文件时，不反复计算全部未变化文件的指纹。
- 文件仍在下载、被占用或来源临时不可用时，不把未完成文件当成正常资料执行。
- 监测可以暂停、退出和恢复，后台运行状态清楚；自动执行另设用户明确启用的范围。

## 7. 阶段四：V1.5，让其他人能够独立安装使用

### 目标

形成 Mac 小范围试用版。

### 工作

- 提供 .app 和明确的安装方式，首次使用引导、权限说明、示例目录及清楚的错误提示。
- 安装后无需用户手动安装 Python、配置虚拟环境或修改个人路径。
- 区分全局偏好、各整理空间配置和历史记录。
- 增加程序版本、更新说明、诊断日志导出、数据库结构版本与升级备份。
- 更新在任务空闲时进行；升级失败能够保留旧配置及历史。
- 公共发布前验证签名、公证、安装后首次启动，以及依赖许可和隐私说明。

Qt 提供官方 [pyside6-deploy](https://doc.qt.io/qtforpython-6/deployment/deployment-pyside6-deploy.html)，可以先做本机部署小样。macOS 对外直接分发的签名和公证流程参考 [Apple 官方说明](https://developer.apple.com/documentation/security/notarizing-macos-software-before-distribution)，不能把开发机上运行成功等同于他人安装成功。

### 完成条件

- 在未配置开发环境的机器或干净用户环境中完成安装、首次扫描、预览、整理和撤销。
- 邀请约五名同学使用各自独立的低风险样本，至少四名能在无开发者现场指导下完成核心流程。
- 记录误操作、理解困难和实际失败，发布前解决文件安全、恢复及安装阻断问题。
- 新旧版本升级后，既有整理空间、手动保护和操作历史保持可用。

## 8. 阶段五：跨平台与跨磁盘分别验收

### Windows

在已有拯救者的 Windows 原生环境构建和验证桌面版本。WSL 测试不代替 Windows 桌面验收。覆盖长路径、保留名称、大小写冲突、权限、占用文件、链接/联接点、不同 DPI 和安装卸载。

Windows 有自身的文件命名和路径约束，参见 [Microsoft 官方说明](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。

### 跨磁盘和外接设备

单独设计“复制到目标临时位置→完整校验→确认目标落位→最后处理源文件”的可恢复流程。校验失败、空间不足、设备拔出或中断时保留足够证据与源数据，避免把跨卷复制伪装为同卷原子移动。

验收除内容和路径外，还要明确覆盖修改时间、权限、扩展属性及平台特有信息。Python 官方指出高层复制函数不能保存所有文件元数据，参见 [shutil 文档](https://docs.python.org/3.14/library/shutil.html)。对无法保留的信息，应限制操作或明确告知。

### 完成条件

- Mac 与 Windows 分别有安装包及原生测试结果，支持矩阵明确列出系统和文件系统范围。
- 跨盘正常、中断、拔出、重启、撤销等场景有独立夹具和恢复证据。
- 使用现有设备先完成验证，不预先购买服务器或升级硬件。

## 9. 阶段六：V2.0，加入可选的智能建议

### 目标

帮助用户判断规则难以解释的零散资料，减少人工分类成本。

### 工作

- 按实际需求逐步增加 PDF/文档内容摘要、截图 OCR、相似资料提示和自然语言生成规则。
- 模型输出转成可查看的分类建议和固定计划；最终文件动作仍经过执行层校验。
- 不确定的内容进入待确认队列；用户能够理解依据、修改结果并撤回建议。
- 本地优先。启用联网能力时，让用户选择允许发送的文件或字段，并能关闭该能力。
- 区分模型命中率、人工纠正率、处理耗时及调用成本，与规则方法在同一批人工标注样本上比较。

### 完成条件

- 在原本难分类的资料上，确实减少人工判断时间，而非只是增加调用步骤。
- 关闭模型和网络后，扫描、规则整理、记录、撤销及恢复仍正常工作。
- 根据实际模型、OCR 规模和内存需求选择 Mac 或拯救者；当前规划不假定需要 GPU 或云服务。

## 10. 近期优先事项与推进方式

下一轮产品开发建议先完成 V1.2：

1. 固化当前可复现基线，建立独立仓库和发布记录。
2. 为任务生命周期统一状态与取消，补齐扫描/恢复的进度和取消体验。
3. 开放完整历史与恢复操作，让用户看懂实际发生的文件变化。
4. 完成文件执行层专项审查，并以真实日常使用记录检验结果。

随后开展 V1.3 规则配置。若实际试用首先暴露规则是最大障碍，可提前交付规则配置的最小闭环，避免把重构当成进入使用的前提。

每轮只设一个用户可观察的主要结果。维护问题清单、发布条件、版本说明和最小复现；先通过对应验证，再扩大使用范围。日期作为计划参考，发布以门槛是否满足为准。

长期优先级：文件安全与恢复 → 本人持续使用 → 规则通用化 → 持续整理与查找 → 小范围试用 → 跨平台与跨盘 → 智能建议。课程报告从真实版本和记录中取材，产品继续迭代。
