# 归档盒：可预览、可撤销的课程文件整理器

日期：2026-11-05。本文为开发前设计，验收结果全部待实测，不代表已完成的软件。应用源码由学生在 TRAE 中逐步开发；本目录不包含应用实现。

## 1. 项目定位

面向大学生日常下载的课件、作业、截图和资料，将“散乱的课程文件”变成“分类清楚、每一步有记录、需要时能撤销”的文件夹。

产品核心不是分类数量，而是让用户清楚知道：哪些文件将去哪里、为何这样分类、实际完成了哪些操作、还能否安全撤销。

建议正式题目：**基于 TRAE 迭代开发的可撤销课程文件整理器：功能演进与可靠性验证**。

课程观察问题：AI 代码工具能否把一个“正常情况下能整理文件”的程序，逐步改进为在同名、内容重复、用户修改及进程中断等情况下仍能正确处理的程序？每次修改解决了什么，是否引入回归，最终还有哪些目标未达成？

## 2. 最终范围先固定

### 必做功能

1. 选择本机文件夹，递归扫描普通文件，显示相对路径、类型、大小。
2. 按文件类型分类；增加用户可配置的课程关键词规则。
3. 整理前预览“原位置 → 目标位置”、分类依据和冲突；允许取消勾选。
4. 用户确认后移动文件，显示实际成功、跳过、失败的数量和原因。
5. 根据内容识别重复组，默认保留每一份文件，不自动删除。
6. 历史记录跨重启保存；允许撤销最近一个尚未完全撤销的整理批次。
7. 遇到撤销冲突、文件被修改、操作取消或进程中断时，保留文件并报告真实状态。

### 本次不扩展的功能

不做账号、云盘、联网大模型分类、OCR、文件正文语义理解、多台设备同步、跨磁盘移动、文件删除和多批次任意顺序撤销。优先验证 Mac；Windows 兼容只在实际运行后报告。实验规模为几十到数百个小文件，不承诺全盘整理性能。

不处理其他进程在单次文件操作瞬间持续并发改写文件的对抗场景，也不承诺断电、磁盘硬件故障后的事务一致性。进程被终止后的恢复是本次明确要验证的目标。

## 3. 文件规则与动作边界

### 3.1 目录结构

用户选定一个测试根目录，在该目录内部整理，避免跨卷移动。归档目录固定为 `_已整理/`，执行记录固定为 `.organizer/`。扫描排除两者、`.git`、系统隐藏文件及符号链接；不跟随外部路径或跨文件系统挂载点。只读扫描不创建分类文件夹或操作数据库。

示例：

```text
测试根目录/
  下载/高数_第一章.pdf
  课程群/高数_作业.docx
  课程群/截图.png
  _已整理/                  ← 执行后生成，后续不重复扫描
    高等数学/文档/
    未分类课程/图片/
  .organizer/               ← 实际执行记录，不计入用户文件总数
```

### 3.2 分类规则

- 类型映射：文档（PDF、Word、TXT、Markdown）、课件（PPT/PPTX）、表格、图片、代码、压缩包、其他。扩展名大小写不敏感；无扩展名归入其他。
- 两种模式：按类型；按课程再按类型。默认先实现按类型。
- 课程规则只匹配文件名，不读正文。比如“高数/高等数学 → 高等数学”“AIGC/生成式人工智能 → AIGC”。
- 多条规则命中时，按界面显示的规则顺序取第一条；未命中进入“未分类课程”。预览显示实际命中的规则，规则更改后旧计划失效，需要重新预览。
- 候选文件按相对路径排序，保证同样输入得到稳定计划。计划生成后固定目标名和文件内容指纹，执行时不得悄悄重算另一套路径。

### 3.3 同名和重复内容

- 同名不等于重复。重复组根据文件大小与 SHA-256 内容指纹判定，文件名仅用于展示。
- 重复组内每一份文件默认都保留；本项目不提供自动删除重复文件。
- 多个来源文件拟进入同一个目标路径时，计划内就分配 `实验报告.docx`、`实验报告 (1).docx` 等唯一名称，并显示更名依据。
- 整理前目标已经存在，也纳入冲突分配；用户可接受更名或取消该文件。
- 预览之后又出现新的目标占用时，执行应跳过受影响文件并要求重新预览，不能临时改名，也不能覆盖。
- 预览后源文件消失或内容改变，同样跳过并说明；其余文件可按原计划继续。

### 3.4 撤销的明确语义

“撤销”是逐项恢复该批次实际移动过的文件，不是删除整个归档目录，也不是把整个文件夹回滚到旧快照。

- 只允许撤销最近一个尚未完全撤销的批次；旧批次可查看。存在中断待处理批次时，先恢复或撤销该批次，再开始新的整理。
- 撤销前检查：当前目标文件是否仍在、内容是否仍等于该批次移动的版本、原路径是否空闲。
- 目标文件被用户修改、目标文件缺失、原路径被新文件占用：不覆盖、不删除，保留现状，列出原因；其他可撤销项继续处理。
- 整理后新增的其他文件不受影响；重复点击撤销不能产生第二次移动或删除。
- 只清理本批次创建且当前为空的目录，不能递归删除装有新文件的目录。
- “完整撤销成功”仅指所有可追踪项恢复；存在冲突必须显示“部分撤销”，不得统一显示成功。

## 4. 界面与交互

产品名“归档盒”，采用简洁桌面工具风格：浅色或随系统外观、蓝色主要操作、橙色冲突提示，中文系统字体。信息以表格为主，避免装饰性大图、复杂动效和无关统计卡。

### 三个页面

**整理文件**：顶部选择目录与分类模式，中间是核心预览表，底部显示实际勾选数量和开始整理按钮。表格列：勾选、文件/原位置、目标位置、分类依据、状态。选中一行可查看完整路径和重复组。

**分类规则**：课程关键词、目标课程名、优先顺序；显示“第一条命中生效”。先使用明确规则，不加入语义猜测。

**操作历史**：批次时间、实际移动数量、完成状态；查看逐项明细、撤销最近批次，启动时提示待恢复任务。

### 状态与反馈

首次使用引导选择目录；空目录说明没有可整理文件；扫描中显示进度与取消；预览后才能整理；执行中禁用重复启动。遇到问题显示具体文件、原因和下一步动作，颜色之外必须有文字。

开始前确认弹窗：目录、文件数量、目标位置，明确“重复文件全部保留”。取消在当前单文件操作完成后生效，保留已完成记录，可撤销已完成部分。

键盘可以完成目录选择后的主要操作；长路径提供完整详情而非只有省略号；扫描/计算指纹不阻塞界面。

Qt 官方安装说明：[Getting Started](https://doc.qt.io/qtforpython-6/gettingstarted.html)。

建议模块职责：

| 模块 | 职责 |
|---|---|
| 扫描器 | 找到范围内的文件，过滤归档目录、隐藏文件和符号链接 |
| 分类器 | 根据明确规则返回分类及依据，不移动文件 |
| 计划器 | 生成固定计划，处理目标重名，记录源内容指纹 |
| 执行器 | 核验计划，逐项移动，保存实际结果 |
| 记录与恢复 | 保存批次及逐项状态，启动时核对未完成动作 |
| 撤销器 | 根据实际结果恢复，处理缺失、修改和占用 |
| 界面 | 展示计划、进度与结果，不自行拼接另一份动作计划 |

记录至少包括批次ID、动作ID、原/目标相对路径、大小、SHA-256、动作状态、错误、时间及本批次创建的目录。逐项记录先保存执行意图，再移动并更新结果；不能只在整个批次结束后写日志。恢复时核对实际路径与内容，不能凭旧状态盲目重放；情况不明确时暂停该项并提示人工处理。

Python 的改名接口在不同系统对已存在目标的行为不同，因此“调用成功”不能直接等于“没有覆盖”，应把不覆盖作为独立验收项。[Python 文件操作文档](https://docs.python.org/3/library/os.html#os.rename)

以下均为**预期标准，当前尚未执行**。所有实验在新建测试目录完成，不对真实下载目录或外接硬盘操作。

| A09 | 整理完成后关闭程序再打开并撤销 | 文件恢复到原位置；重复撤销无副作用 |
| A10 | 整理后在归档目录新建文件 | 撤销保留新文件及其所在非空目录 |
| A11 | 整理后修改一个已移动文件 | 撤销保留修改内容，该项显示冲突 |
| A12 | 整理后原路径被新文件占用；或目标被移走 | 不覆盖新文件、不猜测找回，明确报告 |
| A13 | 取消部分完成的任务 | 完成数与实际一致；可撤销已完成部分 |
| A14 | 终止进程后重启 | 按实际文件核对未完成批次，恢复或撤销不重复移动、不丢失文件 |
| A15 | 文件移动后、结果记录前发生进程中断 | 启动能识别该不确定状态；不能仅因日志未完成而当作没移动 |
| A16 | 符号链接、隐藏文件、归档目录再次扫描 | 不越界、不重复整理自身输出 |
| A17 | 连续点击开始；有未恢复任务时再开始 | 不产生重叠批次，说明应先处理当前任务 |
| A18 | 重复完整整理→撤销流程 | 可复核的结果稳定，历史不是虚假的统一成功 |

A14/A15 可用测试专用检查点让测试进程在指定位置直接退出，以稳定复现操作系统进程中断。它是在检验恢复需求，不修改生产逻辑制造缺陷；如果程序正确应通过，不能把“人为关闭进程”本身记为 AI 失败。若尚未能构造或验证该场景，应标注未测。

### 独立核验方法

由测试准备工具在执行前生成 `相对路径、大小、SHA-256` 清单，放在被整理目录之外。整理后按内容指纹的**多重集合**比较用户文件：重复副本也要计数，不能用集合去掉重复后比较。日志和数据库不计入用户文件。

正常撤销后比较原始“路径→内容指纹”映射。对于用户后来新建或修改的冲突场景，分别核验原有未冲突文件和后来变化的文件，不能要求回滚覆盖新内容。

不能只接受程序自报“PASS”。至少保留目录前后清单、独立检查输出和关键界面截图。故障发生时先保存当前版本、原始输出与最小复现，再让 TRAE 修改。

### 10.2 已定位的三个根因

1. **只匹配文件名**：`_match_course` 只接收 `filename`。而该目录的文件语义几乎全在路径上（如 `已完成期末/Java practical training/xxx.class`、`20251567.zip`），文件名本身不含课程信息。

#### 第 4 层：排除与性能
