# 归档盒 V1.5 长期规则版 · 试用说明（基于 V1.3 规则配置 / V1.4 单文件修正）

> **先读这两句**：
> 1. 整理是**移动文件，不是备份**。首次试用请使用**独立副本**，
>    确认行为符合预期后再整理真实资料。
> 2. 真实 NEU 资料目录在试用期间保持**只读**，不要直接对它执行整理。

## 一、本版新增：不用改源码就能调整推荐模式

推荐模式（「按方向/学期/类别」）的方向、学期、课程目录与关键词兜底，
现在可以在界面里编辑，并**按根目录保存**、重启后恢复。

配置文件位置：`{你选择的根目录}/.organizer/classification_config.json`
（只有你点击「保存并应用」才会创建；只查看/试运行不会写文件。）

## 二、启动

- 双击项目根目录的 **`启动归档盒.command`**（Finder 双击或右键→打开）。
- 复用 `归档盒源码/.venv`；脚本不会自动升级依赖或更换系统 Python。
- 启动失败时终端会给出原因（缺虚拟环境/缺源码），按提示处理即可。

## 三、推荐模式的规则编辑流程

1. 选择目录 →「扫描」→ 确认当前「分类模式」为
   **按方向/学期/类别（推荐）**。
2. 点 **「推荐模式配置…」** 打开编辑器。五张表分别对应：
   - 学期映射：来源目录名 → 学期标签；
   - 顶层方向：顶层目录 → 课程/竞赛/项目/校园事务；
   - 学期内目录：某学期下的一级目录 → 方向 + 类别（类别留空=用关键词细分）；
   - 通用目录前缀：未登记目录按前缀归类（如「附件-」）；
   - 关键词兜底：关键词 → 目标类别，可选匹配范围与触发场景。
3. 每张表里：勾选=启用；行从上到下就是匹配优先级；用「上移/下移」调整；
   「添加一行 / 删除选中」维护规则。
4. 点 **「试运行／查看影响…」**：用当前草稿与已生效配置对比，显示
   - 样本数量、各规则命中数量、未匹配（待定）数量；
   - 哪些文件的原目标/新目标发生变化；
   - 代表性文件的分类依据与预计目标。
   试运行**不移动文件、不创建分类目录、不写历史**，也不计算 SHA-256
   （因此“内容重复”一栏会明确标注未核验）。
5. 满意后点 **「保存并应用」**。保存成功后：
   - 旧预览立即失效，「开始整理」被禁用；
   - 必须点 **「重新预览」** 按新规则生成计划，再确认整理。
6. 点「取消」不会改变已生效规则和配置文件；「恢复默认」会把编辑框
   恢复为内置默认，保存后才真正删除该目录的自定义配置。

## 四、各模式实际使用哪些配置

| 模式 | 使用的规则 |
|---|---|
| 按类型 | 不使用本配置；按扩展名类型分目录 |
| 按课程再按类型 | 使用主窗口「编辑课程规则…」里的课程关键词（只影响该模式） |
| 按方向/学期/类别（推荐） | 使用「推荐模式配置…」中的五类映射与关键词兜底 |

因此，两个配置按钮只在各自生效的模式下可点击，避免“能编辑但当前模式
根本不使用”。

推荐模式的固定匹配顺序：
**学期映射 → 顶层方向 → 学期内目录（类别留空时用关键词）→ 通用目录前缀
→ 未登记目录按目录名锚定 → 待定**。
未匹配的内容进入 `_已整理/待定/…`，不会强行猜测。

## 五、配置损坏或不可用时

- 如果配置文件损坏、版本不兼容、字段非法或不属于当前目录，软件会：
  - 明确提示原因，**保留原文件**；
  - **不允许**推荐模式生成计划（不会静默回退默认规则后继续执行）。
- 处理方式：打开「推荐模式配置…」，用默认规则作草稿修复；
  只有点击「保存并应用」才会覆盖原文件；取消则原文件保持不变。
- 保存失败（如磁盘不可写）时，旧配置与已生效规则保持原样，
  界面不会显示虚假的“已保存”。

## 六、历史中的配置快照

每个批次会保存**当时实际使用的分类配置快照**。历史窗口选中批次后，
下方会显示该批次的配置摘要；以后修改规则不会改变旧批次的记录，
便于解释“当时为什么分到这里”。

## 七、其他日常操作

- **保护目录**：「保护目录…」添加不想被整理的目录；自动识别的项目根
  与程序自身源码默认保护。分类配置**不能**解除这些保护。
- **撤销**：只能撤销最近一个尚未完全撤销的批次；冲突时保留现状并写明原因。
- **核对恢复**：只核对中断批次的磁盘实际状态并补记，不移动文件。
- 取消、关闭等待、冲突、暂停的含义与 V1.2 试用说明一致。

## 八、保存截图 / 导出历史 / 反馈问题

- 截图：`Cmd+Shift+4` 框选窗口；
- 导出：历史窗口选中批次 →「导出…」→ CSV/JSON；
- 反馈：截图 + 做了什么操作 + 对应批次明细/导出文件，追加到
  《归档盒-过程记录.md》或直接反馈给开发轮次。
- 每次试用后按《归档盒-日常试用记录.md》填：日期/目录/文件数、
  分类修正、遇到的问题、撤销/恢复情况。**分类错例请尽量保留**，
  它是下一轮规则改进的输入。

## 九、单文件分类修正（V1.4 新增）

当自动分类对某个文件不合适时，不必改规则重跑。在预览表格里：

> **适用范围**：本功能**只在「按方向/学期/类别（推荐）」模式**下可用。
> 「按类型」「按课程再按类型」模式下按钮为灰色；直接调用也会被拒绝，
> 因为这两种模式不记录方向/学期/类别，无法"恢复自动分类"。
> 需要修正它们时，请用对应的规则配置入口。

1. 选中一行（只支持单行）。
2. 点 **「修正所选文件分类…」** 按钮。弹出对话框，左侧显示当前文件的
   自动分类依据（方向 / 学期 / 类别 / 自动规则 / 自动目标路径），
   右侧是可编辑字段：
   - **方向**：课程 / 竞赛 / 项目 / 校园事务 / 待定（下拉选择）
   - **学期**：课程方向必填；其他方向留空
   - **类别**：分类到该方向下的子目录名（留空则用自动分类的类别）
   - **内部路径**：留空则保持自动分类的内部层级。可以填一层（`实验一`），
     也可以填多层（`实验一/分组报告`），程序会逐段校验后用 `/` 还原成子目录。
     开头、连续或结尾出现 `/` 会被拒绝。
   - **说明**：可选文字，写入历史记录，便于日后追溯
3. **字段实时预览目标路径**——每改一个字段，下方立即更新预计目标。
   路径非法（如包含 `..`、以 `/` 开头、出现空目录段）时字段显示红色，
   且「确定」按钮禁用。
4. 改好了点「确定」。应用后：
   - 当前表格中该文件所在行**整行变黄**，源路径列前加 `✎` 标记，
     tooltip 显示"自动 → 手动"对比；
   - 状态栏提示"已手动修正 N 个文件"；
   - 冲突重新计算（如果两个文件修正后目标重名，程序自动加 `(1)` / `(2)` 后缀）。
5. 要**恢复自动分类**有三种方式：
   - 对话框里点「恢复自动分类」按钮（会连原有「作业」「实验」这类内部目录
     一起还原，不会丢层）；
   - 主窗口选中已修正行，再次点「修正所选文件分类…」→ 改回原始值；
   - **重新扫描 / 重新预览 / 切换根目录**都会丢弃当前计划，自动生效。

### ⚠ 重要：修正只在"本次计划"生效

- 修正**不写回分类配置**，也不影响其他根目录的默认分类。
- 重新扫描 / 重新预览 / 切换根目录 → 当前计划丢弃，手动修正消失。
- 保存配置 → 旧计划同样会立即失效（这是 V1.3 已有的门控，本轮不变）。
- 整理执行后，历史批次里每条记录会标注"分类来源=手动/长期规则/自动"，
  手动修正的行 tooltip 显示"自动目标 → 手动目标 → 修正说明"，
  长期规则的行 tooltip 显示规则标识与命中依据（见 10.4）。

### 与其他功能的互斥关系

| 操作 | 对手动修正的影响 |
|---|---|
| 重新扫描 | 丢弃当前计划，修正消失 |
| 重新预览 | 丢弃当前计划，修正消失 |
| 切换根目录 | 丢弃当前计划，修正消失 |
| 保存分类配置 | 旧计划失效，重新生成后修正消失 |
| 执行整理 | 修正随批次一起入库，历史可追溯 |
| 撤销 | 不关心当初是自动还是手动，只按 SHA 恢复 |

### 取消 = 不改计划

对话框点「取消」或关闭窗口 → 计划不变，什么都不做。
只有点「确定」才应用到当前计划。

## 十、保存为长期规则（V1.5 新增）

如果这次修正以后还会反复遇到，可以在同一个修正对话框里点
**「保存为长期规则…」**，把这次判断固化成规则。

### 10.1 操作流程

1. 在预览中修正一个文件，字段改好后，点「保存为长期规则…」。
2. 弹出规则草稿窗口，自动带入这次的目标分类，你只需要确认/修改匹配条件：
   - **匹配方式**（三选一，没有正则、没有脚本）：
     - **精确路径**（默认）：只匹配这一个文件
     - **目录范围**：整个来源目录；可勾选「包含子目录」
     - **文件名关键词**：文件名含任一关键词；可限定来源目录
   - **来源路径/目录**：按匹配方式填写，目录匹配一律按路径边界判断，
     「课程A」不会误匹配「课程AB」
   - **目标方向 / 学期 / 类别**：沿用现有方向与路径模板
   - **内部路径**：保留自动结果 / 清空 / 替换为指定路径
3. 点 **「试运行」**，下方展示：
   - 命中文件数、目标位置变化数、目标冲突数
   - 代表样本的原位置、旧目标、新目标与命中依据
   - 试运行在**后台线程**执行，计算期间窗口仍可拖动、可关闭，
     按钮与输入框暂时锁定并提示「试运行中……」；关掉窗口会安全取消，
     迟到结果不会再回填。
4. 点 **「保存为长期规则」**，确认框会再次说明影响；确认后写入该根目录配置。
   - 保存只使用**上次试运行的结果**，不会在保存时再同步算一遍；
   - 若修改了匹配条件或目标字段，需要**重新试运行**才能保存
     （下方会提示「匹配条件已修改，请重新试运行」）。

### 10.2 优先级（重要）

```
当前计划的临时手动修正   ← 最高
        ↓
已启用的长期修正规则（从上到下取第一条命中）
        ↓
原有推荐模式映射（学期 / 顶层方向 / 学期内目录 / 通用前缀 / 关键词）
```

因此长期规则**能覆盖**已经命中原有学期/课程映射的文件，
但仍不会改写保护目录的判断——保护目录始终由保护机制控制。

### 10.3 保存后会发生什么

- 规则写入 `{根目录}/.organizer/classification_config.json`，重启后继续生效；
- **当前计划的临时手动修正会一起失效**（保存前会明确提示）；
- 旧预览失效，需要点「重新预览」按新规则生成计划后才能执行；
- 之后可在「推荐模式配置 → 长期修正规则」页查看、编辑、启用/禁用、删除、上移/下移。

历史记录里每个文件都会保留**当时实际命中的规则标识与依据**，
即使后来规则被改、被禁用或被删除，旧批次记录也不会变。

### 10.4 在哪里查看长期规则结果

- **历史窗口 → 选中批次 → 逐项明细**：
  - 「分类来源」列现在有三种取值：**手动**、**长期规则**、**自动**；
    长期规则行以蓝色显示，自动行保持灰色；
  - 把鼠标停在「分类来源」上，可看到**规则标识**（如 `long_term:lt-…`）
    与**命中依据**（例如「长期规则「作业 修正规则」：来源目录
    「大二上/数据结构」（含子目录） → 项目/数据大创」）；
  - 批次列表的「注意」列会显示「⚑ 长期规则×N」，一眼看出该批次
    有多少条是靠长期规则分类的。
- **导出**：
  - JSON 每条动作新增 `rule_key`（如 `long_term:lt-…`）与
    `rule_applied`（命中依据文本）；
  - CSV 新增「规则标识」「命中依据」两列。
  - 旧批次（V1.5 之前）这两项为空，导出时同样保留空值，不做推断。

### 10.5 配置版本兼容

配置格式升到 `version=2`。读取端同时接受 1 和 2：
- 旧配置（version 1，没有长期规则）**可正常读取**，保存时自动升级为 2；
- 新配置（version 2）用旧程序打开会因版本不兼容被拒绝，并保留原文件——
  避免旧程序静默忽略长期规则后继续整理。

### 10.6 取消 / 失败时的状态

- 草稿窗口点「取消」：不写配置，草稿丢弃；
- 规则校验不通过（空名称、路径逃逸、学期与方向不匹配等）：拒绝保存并指出原因；
- 保存失败：原配置文件保持字节不变，已生效规则不改变。

## 十一、支持范围与已知限制

- 支持：单根目录课程资料整理、推荐模式规则配置、按根保存/重启恢复、
  规则影响试运行、**单文件手动分类修正**、**保存为长期修正规则**、
  保护目录、撤销最近批次、中断核对恢复、完整历史（含分类来源与规则标识）。
- 不支持（后续版本）：跨磁盘移动、AI/OCR 分类、目录监测、Windows、
  任意方向与目标路径模板、任意脚本规则、正则规则、多文件批量修正。
- 试运行不计算 SHA-256，重复信息需在正式预览/计划中核验。
- 恢复核对阶段不可取消（有进度显示，符合设计）。
- 整理记录不等于备份；重要资料请先做独立备份。
- 手动修正只支持当前选中的**单行**；多行选中时对话框拒绝打开。
- 手动修正只在**推荐模式**下开放；其他模式请用对应规则配置入口。
- 长期规则同样只在**推荐模式**下生效；不改变「按类型」「按课程再按类型」。
- 内部路径的每一段仍会做非法字符替换，空段（`//`、首尾 `/`）直接拒绝。
- 「恢复自动分类」还原首次自动生成的快照（其中可能已包含长期规则的判断），
  不按当前配置重跑。
- 长期规则名称在同一个配置内必须唯一，便于在历史和界面里区分。
- 规则草稿的试运行在独立线程进行；关闭窗口会请求取消，已开始的那一次
  计算可能在后台再多跑一小段才退出（不阻塞界面、不回填迟到结果）。
- 「保存为长期规则」必须基于一次**当前的**试运行结果；改了条件就要重新试运行。
- 历史导出里旧批次（V1.5 之前）的「规则标识 / 命中依据」为空，属正常。
