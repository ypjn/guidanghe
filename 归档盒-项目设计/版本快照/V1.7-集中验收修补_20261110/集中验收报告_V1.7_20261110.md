## 四、阻断问题：退出期崩溃（已修复）

### 现象

`exit_cleanup_check.py` 在**不显式调用** `shutdown_widgets()` 的路径下，
打印“组合构造与关闭完成，准备退出”后，进程在解释器最终化阶段偶发
`SIGSEGV`：10 次运行中 2 次，操作系统退出码为 `-11`（Shell 显示 139）。
日志与栈（faulthandler）：

```
Fatal Python error: Segmentation fault
Current thread ... <no Python frame>
QObject::~QObject → QWidget::~QWidget → QPushButtonWrapper::~QPushButtonWrapper
→ PySide::destructionVisitor → Shiboken::BindingManager::visitAllPyObjects
→ PySide::destroyQCoreApplication → runCleanupFunctions
→ SbkQtCoreModule___moduleShutdown → atexit_callfuncs → Py_Finalize
```

### 根因

PySide6 6.12 + Python 3.14 在退出阶段统一销毁 Python 包装对象时，
控件 C++ 父对象已先被销毁，`QPushButtonWrapper` 再次析构触发崩溃。
生产入口原本在 `app.exec()` 后显式调用 `shutdown_widgets()`，
因此显式清理路径 10/10 稳定；异常路径或未显式清理的脚本仍可能命中。

### 修复（`main.py`）

在模块导入时注册 `atexit.register(shutdown_widgets)` 作为兜底：
atexit 后注册先执行，早于 PySide 自身的 `QCoreApplication` 清理，
保证无论入口是否显式调用，顶层控件都在解释器最终化前被确定性销毁。
未使用 `os._exit`、强杀线程、关闭垃圾回收等规避方式。

### 复跑

| 场景 | 次数 | 操作系统退出码 |
|---|---|---|
| 显式清理（`--teardown`） | 10 | 全部 0 |
| 非显式清理（修补前） | 10 | 8×0，2×-11（失败） |
| 非显式清理（修补后） | 15 | 全部 0 |
| 显式清理（修补后） | 10 | 全部 0 |
| 生产入口 `main()` 自动关闭探针 | 6 | 全部 0 |

修补后全部回归与规模验收均未再出现退出期崩溃。

1. 重复文件窗口只读，不提供删除/合并/自动勾选/释放空间。
2. 待整理范围扫描为“整空间扫描后过滤”，非增量扫描引擎。
