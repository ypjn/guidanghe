- 严重级别：高 —— 主入口双击后看不到窗口，用户会误判为文件损坏 / 被杀毒拦截 / 没解压完整

## 一、现象

1. 双击免安装包根目录的 `归档盒.exe`：桌面**不出现任何窗口**，也没有 UAC 提示、报错弹窗。
2. 同目录会新建（或被清空）一个 **空的**「启动日志.txt」。
3. 打开任务管理器 → 详细信息：`pythonw.exe` 进程确实在运行，工作集约 **144 MB**，CPU 很快归零（说明 Qt 事件循环已起来）。
4. 重复双击会**累积多个**隐藏的 `pythonw.exe` 进程。
5. 手动运行 `runtime\pythonw.exe app\main.py` 则**窗口正常出现**（约 1 秒）。

结论：程序本体没有问题，问题出在**启动器**。

## 四、证据

### 4.1 启动器确实执行了

每次启动都会在包根目录创建/截断「启动日志.txt」。**空的日志是正常的**：归档盒本身不向
stdout/stderr 写入任何内容，日志只用于说明「启动器跑过」（原启动器把子进程输出重定向到该文件）。

### 4.2 进程起来了，窗口也创建了，但被隐藏

用 `user32!EnumWindows` 枚举「原 `归档盒.exe` 启动出的 `pythonw.exe`」进程的顶层窗口：

```

hwnd=0x1C174A visible=False class=[Qt6120QWindowIcon]              title=[归档盒]      ← 主窗口
hwnd=0x318D6  visible=False class=[Qt6120ThemeChangeObserverWindow] title=[]
hwnd=0x318D0  visible=False class=[Qt6120ScreenChangeObserverWindow] title=[]
hwnd=0x31868  visible=False class=[IME]                            title=[Default IME]
```

也就是：Qt 主窗口（类名 `Qt6120QWindowIcon`、标题「归档盒」）**已经创建成功**，只是
`IsWindowVisible = False`。这不是「没启动」，而是「窗口被藏起来了」。

同一次验证中，该进程工作集约 144 MB、CPU 正常，说明事件循环在跑。

## 五、根因

原 `归档盒.exe`（Go 启动器）以**隐藏窗口的方式**创建 `runtime\pythonw.exe` 子进程。
Windows 的规则是：进程创建时如果 `STARTUPINFO.dwFlags` 带 `STARTF_USESHOWWINDOW` 且
`wShowWindow = SW_HIDE`，该进程**第一次**调用 `ShowWindow` 时传入的显示参数会被系统覆盖为隐藏。

归档盒主窗口的流程是「创建 QMainWindow → `show()`（内部第一次 ShowWindow(SW_SHOW)）」，
这一次显示请求被启动参数覆盖成 `SW_HIDE`，于是窗口对象存在、但从未真正显示；之后的
`show()` 逻辑也不会再被调用，窗口就一直不可见。

在 Go 里这种写法通常来自（推断，启动器源码不在本仓库）：

```go
cmd := exec.Command(pythonw, mainPy)
cmd.SysProcAttr = &syscall.SysProcAttr{HideWindow: true}  // ← 罪魁祸首
cmd.Run()
```

`HideWindow: true` 的本意是「避免弹出黑色控制台窗口」。但这里启动的是 **pythonw.exe**
（Windows 子系统程序，本来就没有控制台窗口），所以这个隐藏完全没必要，反而把 Qt 主窗口
的第一次显示请求吃掉了。

## 七、修复方案

### 7.1 已落地：修复版启动器（`windows免安装启动器/`）

- 文件：`windows免安装启动器/启动归档盒.exe`（7,168 字节，SHA-256 见第十节）
- 用法：复制到免安装包根目录（与原 `归档盒.exe` 同级），以后**双击它**启动即可。
  原 `归档盒.exe` 保留不动（也可留着作对照）。
- 行为与原启动器一致：校验 `app\main.py` / `runtime\pythonw.exe`、工作目录设为 `app\`、
  `PYTHONUTF8=1`、写「启动日志.txt」；**唯一区别是不隐藏窗口**。
- 源码：`windows免安装启动器/launcher_fix.cs`（C#，单文件，Windows Forms）；
  编译：`build-launcher.ps1`（用 Windows 自带 .NET Framework 的 `csc.exe`，无需装 Visual Studio）；
  验证：`verify-window-visible.ps1`。
- 包内说明见 `windows免安装启动器/README.md`。

### 7.2 打包端永久修复（推荐，Go 启动器）

在打包端改动启动器源码，**删除/不要设置隐藏窗口**：

```go
cmd := exec.Command(pyw, mainPy)          // pyw = <包>\runtime\pythonw.exe
cmd.Dir = filepath.Join(base, "app")
cmd.Env = append(os.Environ(), "PYTHONUTF8=1")

// 不要设置 SysProcAttr.HideWindow / CREATE_NO_WINDOW /
// STARTF_USESHOWWINDOW + SW_HIDE —— pythonw.exe 没有控制台，无需隐藏窗口。
// cmd.SysProcAttr = &syscall.SysProcAttr{HideWindow: true}   // ← 删除这一行

if err := cmd.Start(); err != nil {
    // 弹 MessageBox 说明失败原因
}
```

若启动器自身要避免控制台窗口，用 `go build -ldflags "-H windowsgui"`（或 `-H=windowsgui`）
编译成 GUI 子系统程序即可，与「隐藏子进程窗口」无关。

> 注意：启动器源码、打包脚本目前都不在本仓库。建议这次之后把它们纳入仓库
> （例如 `windows免安装包/启动器/`），否则同类问题只能“修发布物”，无法在源头防回归。

### 7.3 应急手工启动（不依赖任何 exe）

在包根目录新建 `启动归档盒.bat`：

```bat
@echo off
cd /d "%~dp0app"
start "" "%~dp0runtime\pythonw.exe" "%~dp0app\main.py"
```

双击该 bat 也能正常出窗口（会闪一下控制台窗口）。

### 7.4 不建议的做法

- 在 Python 里 `win32gui.ShowWindow` / `ctrl.show()` 延迟二次显示：治标不治本，
  且引入平台相关代码；根因在启动器，应在启动器修。
- 用 `CREATE_NO_WINDOW` 替代 `SW_HIDE`：同样会命中「首次 ShowWindow 被覆盖」问题，
  不要用。
