## 问题

课程需要一条能当众重放的整理流程：选一个小目录，看预览，由人确认一条「以后同类文件怎么放」的偏好，关掉再打开后新文件能沿用这条偏好，然后只移动勾选的文件，并能撤销。文件一旦动过，就要能用相对路径、数量、SHA-256 和批次历史说明动了什么、没动什么。

阶段二已经把偏好放进空间 SQLite，并把确认过的规则镜像到该空间的 JSON。阶段三不再扩展偏好模型，只检查这条演示能不能稳定走完，以及移动、取消、中断、恢复、撤销会不会改到不该改的文件。

## 现有流程

主窗口从「选择文件夹」进入。`重新扫描` 只统计空间内的文件。预览按「按方向/学期/类别」生成目标，默认不移动任何文件。

勾选后点「开始整理」，确认框里「确认开始整理」才会调用执行。取消则整批不动。执行只处理勾选行。源文件消失、内容哈希与预览时不一致、目标路径已经有文件，都会跳过，并在结果里写明原因。同名文件在预览阶段就分配出 `名称 (1)` 这样的稳定文件名，执行时不覆盖。

「修改这一行」里，「仅改本次」只改当前预览；「保存为长期规则…」确认后写入当前空间的偏好库。下次打开同一空间，命中的新文件会带上偏好名称、依据和预期目标。

「操作历史」读取该空间 `.organizer/history.db`。「撤销上一次」把最近一个已完成批次移回原路径。原路径上若已有别的文件，提示「原路径已被占用」，占位文件和已移动文件都留下。若批次在改名之后、写完状态之前中断，重新打开后用「核对恢复」对照磁盘：已经不在源路径、且位于目标路径的项补记为已移动；还在源路径的项保持未执行。再核对一次不会把未执行项补记成已移动。

## 阶段三修复

本轮没有修改产品源码。基线 `4d38a689` 上，上面这条路径按现有规则走通，没有出现需要改执行器或偏好库才能继续演示的缺陷。

证据脚本第一次没有跑通，原因在脚本自己：

- 偏好对话框等到异步预览回来才保存。脚本改为使用程序里已有的同步预览路径。
- 直接调用执行器时，待定行默认不勾选，执行器不会为它们建移动动作。脚本在这些场景里先勾选再执行。这与界面上「未勾选的不会移动」是同一条规则。
- 同名样例若落在不同子目录，目标路径并不冲突。把两份笔记都归到同一课程目录后，预览出现 `笔记 (1).txt`。

这些都用同一个 `tests/test_stage3_delivery.py` 复测。

`4f2245b` 的独立复验退回了两处课程材料：

三类执行要分开看：

- **offscreen 自动化。** `QT_QPA_PLATFORM=offscreen`。S01–S04 构造真实 `MainWindow`，调用扫描、预览、勾选、确认框、执行和撤销。确认框被测试桩替换为「取消」或「确认」，提问框默认「否」，撤销时改为「是」。
- **故障注入。** S08 在子进程里完成一次 `rename` 后调用 `os._exit(9)`，父进程再跑两次 `recover_batch`。这不是把图形界面进程杀掉。
- **原生桌面。** 不设置 `QT_QPA_PLATFORM`。`课程交付/拍摄主窗口.py` 打印的平台名是 `cocoa`。它打开主窗口、扫描演示样本并保存窗口像素。画面与 S01 一致：3 个文件，开发说明未勾选且为待定，笔记和项目说明已勾选。后续的确认、第二轮、执行和撤销没有在这个原生窗口里用鼠标点完，那些步骤的证据是 offscreen 主窗口运行。

阶段二要求继续回归的并发保存、失败回滚、备份恢复、单条保存或删除遇到 JSON 写入故障，包含在 `tests/test_stage2_preferences.py` 的 65 项里，本轮与其他套件一起重跑。

## 已知限制

- 没有在 Windows 或 Linux 上运行。
- 没有做真实跨卷移动。样本都在本机同一临时卷。
- 没有调用真实 DeepSeek。预览画面里「识别图片文字」和 DeepSeek 选项保持关闭。
- 原生窗口只抓了首次预览。第二轮偏好、执行、历史和撤销的逐步点击没有另存桌面截图，对应证据是 offscreen 主窗口日志。
- S08 的中断是子进程在改名后退出，不是图形界面崩溃。
- 核对恢复只补记已经落到目标路径的项，不会自动把仍在原处的项继续移完。
- 「仅改本次」的待定行保持不勾选，因此不会进入随后的移动批次。
- 桌面上的阶段一、阶段二总报告分别写到 `e9dff510` 和 `c24e9e89`。那是更早的记录。本次基线是任务指定并在工作树核对过的 `4d38a689`。
- 仓库里若干 `results_*.json` 会在跑套件时被改写时间戳和随机编号。它们没有纳入本次提交；验收以 `课程交付/证据/阶段三回归.log` 的退出码和通过数为准。
