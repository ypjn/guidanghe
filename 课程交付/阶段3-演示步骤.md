# 阶段三演示步骤

复核时先看提交哈希，再按下面的入口重放。自动化证据在 `课程交付/证据/阶段三回归.log`，第一次预览的真实窗口画面在 `课程交付/证据/截图/01-首次预览.png`。

## 样本入口

在仓库根目录执行：

```bash
python3 课程交付/重置演示样本.py
```

它会补上还没有的演示文件。再次运行时，只把本脚本创建过的普通文件写回初始内容。路径上已经存在的用户文件、符号链接，以及链接指向的目录外文件，都不会改写。演示开始前已经存在的空间偏好会保留，这个空间后来再确认的偏好也会保留。只有一开始没有偏好的演示目录，才会在下一次重置时拿掉演示过程中新确认的偏好，于是 `开发说明.md` 回到待定且未勾选。范围外对照如果已经是符号链接，包括指向还不存在的文件，脚本不会跟随。操作历史和其他文件保留。若样本里还有 `_已整理` 或其他资料，扫描行数会多于 3；要得到下面的 3 行预览，先把这些额外文件移出该目录再重置：

| 相对路径 | 内容 |
|---|---|
| `下载/归档盒/开发说明.md` | 接口说明与排期 |
| `下载/笔记.txt` | 高等数学 极限 导数 |
| `项目/AIGC/项目说明.md` | 项目会议记录 |

空间外对照写在 `课程交付/范围外-不要放进样本.md`。扫描结果里不应出现它。

启动程序使用仓库里的 `归档盒源码`，解释器沿用本机已有虚拟环境。演示前把应用数据指到临时目录，避免写进日常使用的方案和最近空间：

```bash
export ARCHIVEBOX_APP_DIR="$(mktemp -d)"
export ARCHIVEBOX_SCHEME_DIR="$(mktemp -d)"
export ARCHIVEBOX_RECENT_FILE="$(mktemp)"
cd 归档盒源码
../归档盒源码/.venv/bin/python main.py
```

本机复验用的解释器是 `/Users/ypjn/aigc/归档盒源码/.venv/bin/python`。若这台机器没有该路径，使用本仓库 `归档盒源码/.venv`。

窗口抓取（macOS cocoa，不是 offscreen）：

```bash
unset QT_QPA_PLATFORM
/Users/ypjn/aigc/归档盒源码/.venv/bin/python 课程交付/拍摄主窗口.py
```

## 手工演示

每一步都从主窗口进入。文件是否被移动，用样本目录里的相对路径核对；内容用 SHA-256 核对；批次用「操作历史」。

1. **选择空间。** 点「选择文件夹」，选 `课程交付/演示样本`。路径栏应显示该目录。此时文件还在原处。
2. **扫描并生成预览。** 点「重新扫描」。状态栏应出现「计划 3 个文件，已选 2」。表格三行：
   - `下载/归档盒/开发说明.md` 不勾选，目标含 `_已整理/待定/`，状态「待定」
   - `下载/笔记.txt` 勾选，依据含「高等数学」，目标含 `_已整理/课程/`
   - `项目/AIGC/项目说明.md` 勾选，依据含顶层目录「项目」
   对应画面：`课程交付/证据/截图/01-首次预览.png`。对应断言：回归日志 S01。范围外文件不在表里。
3. **确认一条空间偏好。** 选中开发说明那一行，点「修改这一行」，再点「保存为长期规则…」。名称填「开发文档按项目归档」，匹配用目录范围，来源目录 `下载/归档盒`，包含子目录，方向「项目」，类别「归档盒」，内部路径清空，范围选当前空间。先预览，再确认保存。关闭窗口。
4. **第二轮。** 在 `下载/归档盒/` 放一份新的 `接口草稿.md`。重新打开同一空间并扫描。这一行应显示偏好名称「开发文档按项目归档」、依据里的偏好编号，以及目标 `_已整理/项目/归档盒/接口草稿.md`。对应断言：S02。
5. **对照「仅改本次」。** 另放 `下载/临时稿.md`。它不会出现在当前这次预览里，先点「重新扫描」。扫描完成后选中这一行，在修正窗口只点「仅改本次」，不要点「保存为长期规则…」。预览目标可以变，偏好库行数不变。待定行默认不勾选，所以它不会跟着后面的批次移动，除非再勾上。
6. **取消确认。** 取消勾选 `接口草稿.md`，点「开始整理」，在确认框点「取消」。两份对照文件的路径和 SHA-256 都应保持取消前的值。对应断言：S03 的「取消后sha=True」。
7. **确认执行。** 再次点「开始整理」，点「确认开始整理」。只移动当时勾选的行。本轮自动化里实际移动了 3 个：开发说明、笔记、项目说明。接口草稿留在 `下载/归档盒/接口草稿.md`。笔记的目标与预览一致，历史里的 SHA-256 与移动前一致。对应断言：S03。
8. **查看历史。** 点「操作历史」。最新批次状态为已完成，三条动作都是 moved，源路径、目标路径和 SHA-256 与上一步一致。
9. **撤销。** 回到主窗口点「撤销上一次」，并确认。笔记回到 `下载/笔记.txt`，SHA-256 与移动前相同，目标路径不再存在。历史状态变为 undone。对应断言：S04。

安全场景不放进这套小样的手工点击，避免把样本弄乱。它们由同一测试脚本在独立临时目录里复现，见下一节。

## 安全场景与证据

| 编号 | 场景 | 日志位置 |
|---|---|---|
| S05 | 预览后源被改、被删、目标被占，三条都跳过，已改内容和占位文件的 SHA-256 不变 | S05 |
| S06 | 两份同名不同内容，预览就分成 `笔记.txt` 与 `笔记 (1).txt`，执行后两份都在 | S06 |
| S10 | 两份同名同内容，同样分成两个目标，SHA-256 都保留 | S10 |
| S11 | 目标上已有相同内容，仍按「目标路径已被占用」跳过，源和占位都不改 | S11 |
| S07 | 第一项移动后取消，第二项留在原处，批次为 cancelled | S07 |
| S08 | 子进程完成一次改名后 `os._exit(9)`。重启后核对：已移动 1、仍未执行 1。再核对一次不再移动 | S08 |
| S09 | 撤销时原路径已被别的文件占用，提示「原路径已被占用」，占位文件和已移动文件都保留 | S09 |

S01 到 S04 走真实主窗口。S05 的扫描和预览也走主窗口，随后直接调用执行器，以便在预览之后改文件。S07、S08、S09 是执行器与历史库上的取消、故障注入和恢复，不经过确认框。

复跑整套：

```bash
cd 归档盒源码
QT_QPA_PLATFORM=offscreen ../归档盒源码/.venv/bin/python tests/test_stage3_delivery.py
```

退出码 0，且末行是「合计 17 项：通过 17 / 未通过 0」。S12 检查已有文件和指向目录外的符号链接都不被改写。S13 检查空演示目录保存偏好后再次重置，`开发说明.md` 回到待定且未勾选。S14 检查从未做过演示的整理空间，原有偏好不被删除。S16 检查这类空间在重置之后新确认的偏好，再次重置仍保留。S15 检查清单临时文件名上的符号链接。S17 检查范围外对照是悬空符号链接时，不在目录外创建文件。
